# Подготовка CSV к импорту — 1 ноября 2026

Новый законченный сценарий CSV Workbench: CSV поставщика/CRM → явное
сопоставление столбцов → проверка → файл принятых и отдельный файл отклонённых.
Это реализация в приложении, не план и не настройка редактора.

## Изменения

- `import_pipeline.py`: инспекция заголовка и примеров, выбор/порядок/переименование
  столбцов, обязательность, text/integer/decimal/email, составной уникальный ключ.
  Невалидные строки сохраняются в отдельной выгрузке с причинами и исходными ячейками.
  Проверки ограничены лимитами ввода и проектируемых ячеек; нет записи пользовательских
  файлов на сервер и внешних запросов.
- `app.py`: локальный `/api/inspect`, схема в `/api/clean`, новый UI-ассет в allowlist.
  Прежняя очистка без схемы сохранена. Семантика чисел/ключей описана в README.
- `public/workbench-ui.js`: отдельный интерфейс сопоставления, перемещение столбцов,
  типы и ключи, две таблицы результата и две CSV-выгрузки; RU/EN/ES.
  При изменении источника схема сбрасывается, старые результаты скрываются.
- `public/app.js`: существующие переводы базового интерфейса; логика выделена
  в workbench-ui.js. `index.html` и `style.css`: рабочая область импорта и мобильный вид.
- `tests/test_import.py`, `tests/test_app.py`: предметные и HTTP-проверки.
  `tests/browser-import.mjs`: реальный сценарий Chrome со скачиванием файлов.
- README EN/RU/ES: порядок использования и ограничения новой функции.

## Проверка

Bundled Python 3.12.14:
`python -m unittest discover -s tests -v` — **20 тестов, все прошли, exit 0**.
Перед финальным успешным прогоном одна попытка получила WinError 10053
при локальном HTTP-соединении. Полный повтор прошёл; точная причина единичного
сброса не установлена. Это ограничение воспроизводимости проверки, а не скрытый pass.

Headless Chrome через установленный Playwright:
`node tests/browser-import.mjs` с PYTHON_EXE/PLAYWRIGHT_MODULE/QA_OUTPUT — exit 0.
Проверены выбор/исключение, переименование и порядок столбцов, required/type/key,
скачивание и содержимое обоих файлов, RU/EN/ES без потери схемы, ширина 390 px
без горизонтального переполнения страницы, сброс схемы после изменения источника
и прежняя очистка без схемы. Тестовая база — синтетические записи.

Пример: пять записей данных, одна принята, четыре отклонены:
неверный email/decimal, повтор ключа, пустое обязательное поле, лишнее/недостающее
число столбцов. `001` в скачанном CSV сохранился как строка.

Запущена новая локальная версия на `http://127.0.0.1:8802` после проверки,
что порт недоступен. Readiness: POST `/api/inspect` → 200; контрольный
POST `/api/clean` → 1 принятая, 2 отклонённых записи. Данные обработаны в памяти.
Рабочий процесс оставлен доступным Денису; временный браузер и тестовый сервер
закрываются проверочным скриптом. Запись запуска — в игнорируемом
`code/product-launchpad/runtime/csv-workbench/` (относительно workspace).

Ничего из прежних `.vscode` не удалялось и не редактировалось.
Другие проекты, VPN, рабочий Telegram и MeetScribe не менялись.
Staging/commit/push и публикации не выполнялись.

## Границы

Проверка email только синтаксическая; числовые типы проверяют строку без
автоматического преобразования валют/дат/десятичной запятой. Ключ сравнивается
с учётом регистра, первая корректная запись выигрывает. Требования конкретной
CRM/магазина надо явно задать в сопоставлении. Приложение не импортирует
автоматически в стороннюю систему и не заявляется публичным сервисом.
